## State of the Parakeet impl — what works, what doesn't

### ✅ Works
- Compiles clean against `ort = "=2.0.0-rc.10"` with `local-stt-parakeet`.
- `dimmy_lib::parakeet::transcribe(&[f32]) -> Result<String, _>` end-to-end:
  mel → encoder → greedy TDT decode → vocab → text.
- 22-clip Italian corpus run via `dist/parakeet-test/run_corpus.ps1` —
  output matches the Python `onnx_asr` reference byte-for-byte.
- `parakeet_smoke.exe` (one WAV) and `parakeet_bench.exe` (3 fixtures
  cold + warm) both ship in `core/target/release/` and in the
  self-contained `dist/parakeet-test/` folder.
- 2 unit tests pass (`vocab_size_and_blank_match_bundle`,
  `bundle_dir_returns_path`).

### ✅ Also working now (added in second pass)
- **FFI exposure**: `dimmy_parakeet_bundle_present` /
  `dimmy_parakeet_download_bundle` (blocking + progress events) /
  `dimmy_parakeet_transcribe(pcm, len, buf, buf_len)` — all in
  `core/src/ffi.rs`, mirroring the whisper-model surface.
- **`core/tests/parakeet_e2e.rs`**: 3 tests gated on bundle presence
  (skip clean if missing). Italian transcripts on 3 fixture lengths,
  byte-identical determinism on warm calls, Ok("") on empty input.
- **`onnxruntime.dll` Velopack bundling — Win path wired locally**:
  `scripts/download-onnxruntime.ps1` fetches a pinned 1.22.0 zip into
  `core/target/onnxruntime-win-x64-1.22.0/`. `Dimmy.Windows.csproj`
  has a new `CopyOrtDll` target that conditionally copies the DLL +
  `onnxruntime_providers_shared.dll` into `OutputPath` next to
  `dimmy_lib.dll`. Conditional on `Exists()` so builds without the
  Parakeet feature stay backward-compatible. Verified end-to-end
  locally with `dotnet msbuild -t:CopyOrtDll`.

### ⚠️ Still TODO (for shipping Parakeet to users)
- **Model bundle (~2.5 GB) is not bundled in the installer** — by
  design, would balloon the download. Strategy: ship empty,
  `download_bundle()` triggers from a Settings UI button on first use
  (mirrors whisper.cpp model-download flow). UI not yet wired.
- **release.yml change needed** to (a) run
  `scripts/download-onnxruntime.ps1` before the .csproj build step,
  and (b) add `local-stt-parakeet` to the cargo features when
  building `dimmy_lib.dll`. Not in this branch — change touches CI
  invariants and needs review per `docs/dev/windows-ci.md`.
- **Mac path equivalent**: equivalent script + `.csproj` (or
  Xcodeproj) target for `onnxruntime.dylib`. Not started.
- **UI hooks**: Settings dropdown to pick Parakeet vs whisper.cpp,
  download CTA when bundle missing.
- **CUDA / CoreML untested** — feature flags
  `local-stt-parakeet-cuda` / `-coreml` exist and pass through to
  ort, but no machine here has the right setup to validate.
- **One clip in the test corpus (`2026-05-02_23-23-03`) returns empty**
  string consistently across runs. Likely near-silence post-VAD;
  worth confirming against the Python reference.

## What NOT to do

- Don't introduce a Python sidecar — the project's single-binary
  install story is the wrong place for that.
- Don't bump `ort` to rc.12+ until the VitisAI compile bug is fixed
  upstream. Pin stays `=2.0.0-rc.10`.
- Don't change the FP32 → INT8 default — the Italian-audio quality
  regression on INT8 is not subtle (per user's own benchmark:
  "Sì sarebbe" → "Sarebbe").
- Don't ship the 2.5 GB bundle inside the installer. Download on
  first use from Settings.
